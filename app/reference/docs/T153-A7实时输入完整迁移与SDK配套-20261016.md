# T153 A7 实时输入迁移与 SDK 配套

本轮将原来仍在 Linux 硬件接口中的秒沿、RTC、辅助模拟量采集移到独立 A7 CPU3。Linux 保留共享数据导入、保护业务、CAN/101/104、维护、日志和录波写盘。所有修改在 RT_MPU，原 DTU 工程和原厂 SDK 未改。

当前是实机运行的 v28 实验配套，不能称为全部外设和生产保护验收完成。尤其不能用已有 ADC 波形替代 GPS、测频、直流量校准、触点或断电保持的验收。

## 交接和生命周期

- 采集状态页 `0x442f0000`，辅助快照偏移 `0x600`，固定宽度ABI v1、320字节、独立seqlock；RTC请求偏移 `0xe00`，52字节，epoch/CRC/请求号/回读ACK。
- Linux提供独立 `/dev/rt_mpu_aux`，应用不争抢ADC独占控制fd。平台适配同时检查原生时标年龄和Linux缓存年龄，不能反复读取旧共享页续鲜；GPADC每个通道单独检查时标。
- 共享内存传固定宽度数值与偏移，不能跨核传Linux虚拟地址或系统对象指针。
- Linux设备树禁用TWI1原消费者，新增 `rtmpu,a7-realtime-io-v1` 节点。GPADC0/2和RTP原节点须已禁用；Linux先取得时钟、复位、引脚和空闲捕获通道，再交给A7。PWMCS0控制器和PB13调压输出保留。
- STOP必须同时确认ADC撤源与辅助采集active=0，之后才能释放Linux所有权。释放不明时保留现场，不强卸载模块。PREPARE只启辅助采集，不触发ADC；每次固件启动最多一次START，STOP封闭后不能重放启动。
- RTC启动环已拆开：先A7辅助采集，再读取有效RTC/等待外部UTC，最后软件时间锚和ADC START。无有效时间时保持SSH和辅助诊断，不假造日期。
- Linux当前仍为2ms/FIFO80/CPU2/mmap导入、5ms/FIFO70/CPU1保护，16回路原业务逻辑和定值、校准不改。新增硬件I/O不放到Linux采集或保护线程执行。

## 本轮发现并修正的问题

首候选v26/v27在ADC准备阶段返回-4，没有有效帧，原失败证据保留。根因是GPIO旧bank布局和PK11复用错误：T153/sun8iw22首bank偏移0x80、步长0x80，不能用旧0x30布局；PK11捕获复用须为6。已加入真实PA0/PB11/PB14/PK11地址断言、GPIO bank地址表核对，并保护PA4、PA5和PB13。

Linux捕获IRQ需沿irq_data父域找到最终GIC hwirq51；wakeupgen域的19是SPI编号，不能直接和51比较。修复后同一RT内核上v28正常资格并持续采集。

开机worker在RTC恢复Linux UTC后，仍可能读到上一份PREPARE／未ARM报告。现先在原有期限内等到原生运行态，再核对周期配置；等待不会无限续期。对应正常推进和超时两项回归均通过，最终worker已更新并回读，当前采集没有因此再次启停。

网页辅助卡之前被Python字段白名单过滤，快照扩展后又超过旧16KiB接收上限；现与应用端统一32KiB完整行边界，并保留uint64字符串精度。GPADC年龄改为24MHz tick除24得到微秒，避免误报陈旧；新增卡使用明确未知、未取得周期和资源冲突状态。实际浏览器桌面及620px窄窗口通过，无页面脚本错误，未启后台自动诊断。
