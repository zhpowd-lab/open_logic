## 启动

periph3 安装 Node.js 后，双击本目录 `start-periph3.cmd`；它只为本次进程设置 `RT_MPU_DEVICE_IP=192.168.64.240` 、`RT_MPU_CONSOLE_PORT=6003` 和 `RT_MPU_CONSOLE_PROTOCOL=telnet`，再调用支持UNC路径的通用 `start.cmd`，沿用已有设置和录波。入口优先使用桌面自带Node/Python，保留显式Python路径；依赖安装或FFT打包失败立即退出，避免在错误目录运行服务。设置 `RT_MPU_NO_BROWSER=1` 可只运行本机服务而不打开浏览器，网页端口跟随 `RT_MPU_UI_PORT`。通用入口或直接 `npm start` 使用既有默认值，连接其它目标时先设置下述环境变量。依赖可执行 `npm ci` 安装，启动前自动生成 FFT 浏览器包。

环境变量 `RT_MPU_DEVICE_IP`、`RT_MPU_WAVE_PORT`、`RT_MPU_UI_PORT` 可改变连接地址和端口。健康控制台默认使用原始 TCP 6003；当前 periph3 系统的6003提供Telnet，需要同时设置 `RT_MPU_CONSOLE_PORT=6003` 与 `RT_MPU_CONSOLE_PROTOCOL=telnet`。`RT_MPU_CONSOLE_PROTOCOL` 默认为 `auto`，23 自动协商 Telnet，其它端口采用原始 TCP；明确转发 Telnet 到其它端口时可设置 `telnet`。本机设置保存在 `settings.json`，录波和统计保存在 `captures/`；这两类运行数据不提交到 Git。

## 操作

- 板卡菜单筛选公共板或回路 1～16；勾选 1～8 路波形。始终接收完整 80 路，选择只改变电脑显示。
- `ADC码` 显示原始有符号采样值；`A / V` 按通道表换算。时域自动纵轴围绕零点，原始码和工程量曲线、瞬时值都保留正负号；频谱为非负幅值。测量表始终按当前通道系数换算，单位按钮只切换曲线纵轴。总 RMS 包含直流分量，交流 RMS 去除直流，不能把恒定非零读回的总 RMS 当作交流电流。窗口读回列区分原始码有变化、恒定、样点不足和无有效样点；恒定说明不代表采集故障或输入为零。
- 鼠标左键框选放大，滚轮以鼠标位置为中心缩放，中键拖动平移；方向按钮依次切换横向、纵向和双轴。双击或复位按钮恢复范围。
- 游标 A/B 按钮后点击波形，显示时间及第一条曲线的幅值差。频谱页显示各条曲线的 Hann 窗 FFT，幅值单位为峰值；主峰读数属于第一条曲线。
- 页头明确显示实时、暂停、后触发记录或等待读回状态，全屏仍可见。暂停仅冻结显示，后台读回状态另行显示；继续结束尚未完成的后触发记录、取消布防并返回实时显示。按钮高亮与状态等待后台快照确认，暂停不会解除布防或终止后触发记录。浏览器断连即时标明服务断线、禁用显示控制，首个重连快照确认后恢复。无样点窗口移除旧曲线，避免当成当前读回。布防按所选通道的 ADC 码触发，达到条件后保存触发前后数据并冻结。断线或真实远端故障也保存最近波形。
- 波形自动重连，每 15 秒独立读取装置控制台、启动编号和当前采集归属，区分波形断线、心跳在线但无样点、远端故障及完整应用/独立探针。断线冻结在收到新样点后自动恢复；手动暂停与阈值触发冻结保留。控制台快照显示读取时间，不能把旧快照当成当前状态。
- 清运行状态清零本机监测窗口：样点数、间隔统计、IRQ 峰值、超限和未知计数、重连次数及发送丢帧基线。保留波形、触发设置和历史事件；装置 IRQ 历史最大值仍保留，单独显示。
- 右上角全屏按钮展开波形。浏览器允许时使用系统全屏；内置浏览器受限时占满网页，退出按钮恢复布局。
- 设置按钮可修改通道名称、单位、`a` 和 `b`，换算为 `a × ADC码 + b`。这些设置只影响电脑显示与导出，不修改保护定值、ADC 量程或硬件标定。

## 通道与系数

映射与 `equ_get_ac_channel` 一致：ADC1 为公共电压和辅助输入；ADC2～5 分别对应回路 1～4、5～8、9～12、13～16。读取顺序为 A0/B0/A1/B1；保留第 10 回路 Ic/I0 交换。前八路电压名称按现有 `equ_cfg_5adc_16sw.bin`，实际相电压/线电压接线仍待现场核对。

网页默认通道表按 ±10 V 换算。三相系数沿用 DTU5 的 `SCALE_CT_10A_604`，I0 按 5 A/2.5 mA、1.4 kΩ 负载换算；公共电压按 `factor_e_k_channel` 中 51 kΩ/100 Ω 和放大增益换算，并适配 ±10 V。完整应用向远端下发原 BSP 量程配置；网页没有自动导入装置量程/校准文件，需要保持通道 `a/b` 与实际配置一致。未重新加量比对，因此状态为“标称 / 未校准”。辅助输入的 V 是 ADC 引脚电压。

频率只有在原始峰峰值至少 8 码、至少三个有效过零且样点连续时才显示。零漂和不连续波形不显示为工频。总 RMS / 总交流 RMS / DC 来自完整当前有符号窗口，没有先抽点；总交流 RMS 去 DC。另有标称 50 Hz 基波 RMS：取末尾最多 2048 点（向下取 2 的幂），去 DC、Hann 窗，使用中心格及相邻两格的 FFT 能量并按窗平方和归一；不追踪实际频率，不等同保护基波算法。基波至少 4 周波，THD 至少 10 周波且覆盖 2～25 次谐波，公式为谐波有效值平方和开方 / 基波有效值 × 100%。6400 Hz 下 500 ms 原始窗口使用 2048 点 / 320 ms FFT；100 / 200 ms 分别用 512 / 1024 点，THD 显示未知。表格另列 FFT 实际点数与时窗。断序、明确估算/无效样点、不均匀时标或短窗不输出零值；旧流质量标记缺失注明未知，不能当物理 ADC 证明。有限窗、偏频和噪声影响频带估计；弱信号/噪声中的非零 50 Hz 频带或 THD 不能证明真实工频输入，不按任意工程量阈值把噪声清零；未现场标定的 A / V 是标称系数换算，暂停/故障/离线的测量只属于冻结或末次窗口。

## 录波格式

网络流为自定义 RWF 帧头加样点记录，不是完整的 CFG 文件流。RWF1 头 64 字节，RWF2 头 96 字节；它们的样点是 176 字节 COMTRADE 1999 `BINARY` 记录。RWF3 头 128 字节，样点 192 字节：前 176 字节仍是 4 字节序号、4 字节相对微秒、80 个 int16 模拟量、4 个 uint16 数字字，后 16 字节为 UTC 秒 uint64、纳秒 uint32、有效标记 uint32。所有多字节字段为小端，电脑兼容 RWF1/2/3。

导出生成配对 `.cfg`、`.dat` 和诊断 `.json`。DAT 始终保留原始码，每点仍为 176 字节；CFG 含通道名、相别、单位、`a/b`、采样率和起止时刻。CFG 为 UTF-8，日期按 UTC 导出；网页按 UTC+8 显示。RWF3 的有效 UTC 来自 E907 软件 RTC，使用采样沿估计计数打时标；初始日期来自 Linux 软件时间，没有 PPS 锁定。旧流或无效时钟仍使用电脑接收时间估计，并在 JSON 明确标记。前三个数字字为最近有效值的保持结果，第四字保留；数字量尚未提供每帧有效位到网络，不能用这个显示验证 SOE。

RWF2 追加本批 IRQ 最大值、对应样点号、首次 TIMER3 计数、随后读取的 24 MHz 单调时钟和有效/未知/≥3 μs计数。本机将新的窗口最大值写入 `monitor.jsonl`，明确区分 E907 单调时间和电脑记录时间。此统计是中断到期到首次计数器读取的入口上界，包含该总线读取；不是 ISR 完整执行时长，也不是 PWM 引脚抖动。

RWF3 同时提供时间代次、质量、源和 IRQ 峰值的 UTC 入口时标。阈值、缺口、RTC 错标和故障事件携带受影响样点时间；断线只有最后有效样点时间，不能当成真实死机时刻。独立探针支持手动 `echo sync_rtc > /proc/rt_e907_probe` 从 Linux 校时，当前完整应用尚无此接口、时钟质量为未同步；不要在完整应用中照搬探针命令。运行状态增加 UTC 秒进位与异常计数。Linux 时钟必须先正确设置；纳秒字段与约 41.667 ns 计数分辨率不代表绝对 UTC 有同样精度。

## 严格停止与连续诊断

运行诊断区分别显示当前新样点状态、已由 E907 确认的处理模式、最近原因及九类错误次数。模式与计数只采用 `adc_diag_valid=1`、同一 RWF epoch、完整且新鲜的健康快照；Linux 只确认接收年龄不超过 3 秒的完整组；网页年龄叠加健康快照在电脑的观察年龄，健康检查约 15 秒一次，未核对、合计超过 45 秒或跨会话显示未知，不能把本机请求模式当实际模式。次数是本固件生命周期累计的饱和值，清网页统计不清装置计数；丢弃事件不等于精确漏采样点数，恢复真实读取事件包含启动资格阶段，不能当发布帧数。软件 tick 是 24 MHz 错误观察时标，不是物理沿或 UTC。

连续诊断保留错误计数，继续真实 BUSY 合法读取，错误帧跳过且不估算。历史诊断错误不冻结网页；流中的 active fault 仍表示采集停止。仅新会话首点或同会话前进的样点序号与单调时标刷新实时状态，空心跳、重复样点及明确无效/估算的末点不能延期“在线采集”。没有新点仍标停滞；继续／暂停仅影响显示，不发送 ADC 启停命令。有运行错误时不能据连续显示宣称 ADC/BUSY、稳定性或输入工程量验收通过。

## 独立运行诊断（2026-10-11）

原波形服务继续使用 8098，详细 E907/Linux 诊断由单独的 `debug-server.js` 在回环 8099 提供；双击 `start-debug.cmd` 或运行 `node waveform/debug-server.js`。Windows 入口用 `pushd/popd` 支持 UNC 项目路径，优先选择桌面自带 Node/Python；已经指定的 `RT_MPU_PYTHON` 保留，桌面 Node 不存在时才查找 PATH。首页“运行诊断”链接打开独立页面，不需要重启波形服务，既有通道、系数、触发、暂停和统计起点保持。伴随服务不连接 6011，不创建波形消费者。

新页面默认只在点击“读取一次”时请求 `/api/debug`；可选每 2 秒刷新，等上次请求完成再计时。页面隐藏、离开或关闭会停止刷新并取消请求；浏览器返回缓存页面恢复手动模式，不自动重新查询。多个页面共用一个在途 helper，最后请求者离开会取消 helper，进程真正退出后才能发起下一次。没有独立 debug 页面请求时，不进行新的详细诊断读取；原波形页已有 15 秒必要健康摘要仍保留。

`tools/wave_debug.py` 复用已归档的 SSH 主机密钥策略和已有口令文件，只读 `/proc/rt_e907_probe` 并通过应用 UNIX socket `/run/rt_mpu_dtu/debug.sock` 发送固定 `snapshot\n`；不发送 6000 `rt`/`adc` 命令，不启动或停止 ADC。应用由独立 `rt_mpu_debug_snapshot` 生成有界 JSON，原 `rt_printf` 实现、业务调用和既有路由保持；当前常驻后端日志实际落stdout.log，新诊断不经过rt_printf。工具不输出口令或原始 80 路 `data`/全部事件。每个原始诊断限制 16 KiB，超长、截断、多行和版本不符均失败，不把残缺内容当成功。

页面按“概览、采集、保护、E907 故障、队列与平台”分组，切换标签保留当前选择，不额外读取。支持方向键及 Home/End 导航。分别显示真实调度策略/优先级/CPU、读取/校验/复制/释放、保护导入/业务/完整周期、积压与首错、16 回路计数和 E907 BUSY/DMA/九类错误缓存。`uint64` 以十进制字符串传递，差值用 `BigInt`；配置或会话变化不计算连续增量。缺项和读取失败保持未知，不复用旧快照当当前状态。最大耗时是程序会话累计最大值，不是 2 秒窗最大值；`mmap` 映射是 Linux 私有批缓冲区，不意味着直接映射 E907 DDR。
