# T153 16路总线遥信与定频逻辑采集

2026-10-15。已按用户要求实现主板数据总线本地16路开入：每路1 bit，CS5每周期只读取一个16位字，先读遥信再读五片ADC。DI-only模式使用固定频率，80kHz在20秒扫描/交付窗口和约1秒原始捕获窗口通过；100kHz共享环满，未通过。试验结束已恢复正常A7五片ADC＋DI和完整Linux应用，当前设备没有停留在DI-only模式。

## 位打包与读取顺序

| 项目 | 实现 |
|---|---|
| 16路遥信状态 | 一个 `uint16_t`，状态合计2字节；bit0～bit15为逻辑DI1～DI16。 |
| 总线读取 | 只选CS5，一笔2字节IDA PIO事务；不读取CS6。 |
| 共享样点 | `digital_words=1`，状态为 `digital[0]`，有效位为 `digital_valid[0]=0xffff`；其他数字字和有效位保持0。 |
| 电平与有效性 | 0为原始低电平，1为原始高电平；valid为0的位是未知，不据此伪造闭合。原业务低有效语义由既有入口保留。 |
| 正常采集顺序 | 真实BUSY完成后先取DI，再依次取ADC0～4；同一共享帧上送。 |
| Linux接入 | 原2ms reader完成校验、复制与ACK后，导入同帧DI缓存及原保护/测量/录波数据；本地GPIO入口读缓存，不访问LBC。 |

状态没有逐路使用16位或32位变量，也没有采用跨编译器布局不确定的C位域。读取某路使用 `(digital[0] >> bit) & 1U`。

有效位图、序号、时标、CRC属于额外元数据。为复用既有共享环和ADC格式，**完整共享记录仍为256字节**，DI有效状态只用其中2字节；这次没有将整个运输记录压缩为2字节。DI-only帧的 `analog_count=0`、`valid_chip_mask=0`，不设置ADC有效/估算位，不伪造ADC数据或真实BUSY资格。完整应用打包工具拒绝DI-only固件，避免误启动保护。

## 固定频率与时标

独立A7专核按24MHz单调计数器的绝对期限读取，不采用“读完再延时”的累积周期，也不使用无等待吞吐率作为逻辑分析档位。迟到跨过的周期只计 `missed_periods`，不补点。这里沿用A7专核轮询，没有新增硬件定时中断或输入边沿捕获。

DI-only样点时间戳是**软件读取入口实际计数**。80kHz名义周期12.5µs，20秒实测相邻入口为11.958～13.125µs，因此不能称为无抖动硬件采样。VCD按实际tick换算到1ns时间轴；CSV保留24MHz原始计数。纳秒刻度不是1ns采样精度，1tick约41.667ns。

正常ADC＋DI帧保留原ADC转换时标规则；DI实际在BUSY完成后的读入口取得，不把该ADC时标当成DI输入边沿发生时间。

编译宏见 `a7_amp/acquisition/bus_di.h`：

```c
#define AMP_BUS_DI_ONLY 0              /* 正常ADC＋DI；显式设1才独立测DI */
#define AMP_BUS_DI_PERIOD_TICKS 2400    /* DI-only缺省10kHz；80kHz用300 */
```

头文件的实际缺省按模式区分：正常模式周期宏为0、DI-only为2400。构建脚本禁止DI-only使用零周期。离线构建80kHz例子如下，不会安装或启动设备：

```sh
bash tools/build_amp_acquisition.sh NEW_OUTPUT_DIR 31 1 24 1 0 0 1 300
```

`AMP_BUS_DI_ONLY=1`不复位/配置/触发/读取ADC，公共总线读写仍有超时、空闲及错误检查。正常模式DI读取后恢复ADC的32字节长度，保留原PWM读窗和真实BUSY条件，不为新增DI放宽窗口。

## 板端实测

本轮实验使用已驻留的 `5.10.198-rt97-rtmpu-periph3-a7-rt` / build #2，Linux CPU0～2、CPU3裸机A7，E907 offline。DI-only接收端为CPU2 / SCHED_FIFO80；通过原单消费者机制取得消费权，直接mmap读取共享环。ADC及完整业务在独立测速阶段停止，恢复阶段只使用正常采集配套。

| 40kHz / 600tick | 20s | 800,057 / 800,057 | 0 / 0 / 0 | 有界通过，总线均1.536µs、最大2.833µs。 |
| 80kHz / 300tick | 20s | 1,600,276 / 1,600,276 | 0 / 0 / 0 | 有界通过，总线均1.535µs、最大2.792µs。 |

恢复后的两个新鲜端点处于同boot、同源会话、同APP/starttime及配置，间隔约696秒：源新增8,901,398次读取，DI导入新增8,911,678帧，16回路全部推进。两组端点读取非原子，不将其差值当漏帧。所核源错误、reader拒绝和跳期、保护跳期无新增；reader会话累计跳期2、保护0仍保留。会话累计reader最大整轮3.128417ms、保护最大整轮2.182333ms、最大送达年龄1.928667ms，仅为本PID有界记录，不称长期最坏或40ms触点验收。
